## Why

当前全局顶栏只承载品牌、项目名与一个「设置」入口，信息密度低而占一整条 chrome；用户在 Codex 式三栏原型（`design/04-设置入侧栏原型.html`）中确认：设置入口应移入第一栏（侧栏）底部，以账户行形态呈现（原型变体 B），点击菜单中的「设置」进入主区整页设置（原型变体 A）。同时用户要求 Apple 皮肤吸收 macOS 特有的磨砂（vibrancy）质感。

## What Changes

- **去全局顶栏**：移除 `<nav>` 顶栏（品牌、面包屑、设置按钮），品牌移入侧栏头部；⌘B 折叠/展开侧栏保持不变，折叠后主区左上角浮现展开按钮
- **侧栏 = chrome**：侧栏头部（品牌 + 折叠）→ 新建审阅 → 分组项目列表 → **底部固定账户行**（默认模型 + 就绪状态），点击弹出菜单（设置 / 切换主题风格 / 重新运行引导），菜单底部为版本与本地隐私脚注行
- **设置页入主区**：`ui.page === 'settings'` 时主区渲染设置页（侧栏保留可见），页头提供「← 返回审阅」；点侧栏任意项目即返回工作台
- **瑞士身份保留**：侧栏头部下边线在瑞士皮肤下为 6px 墨线（承接原顶栏的墨线语言），Apple 皮肤为发丝线
- **Apple 皮肤 macOS 磨砂打磨**：浮层（`.pop` 菜单族）增加 macOS 系统菜单影；菜单项 hover 改为 accent 填充 + 白字（macOS 菜单选中语法）；撤销浮条改为磨砂玻璃胶囊卡（macOS 通知形态）；侧栏选中行改为 accent 淡填充 + accent 标题（macOS 侧栏选中语法）
- 原型裁决回填：`design/04` 头注与 `design/README.md` 登记胜出组合（B 账户行 + A 设置页）

## Capabilities

### Modified Capabilities

- `review-ui`: 顶层导航（原「审阅/设置」两入口顶栏）改为侧栏 chrome：品牌、新建、项目列表与底部账户行全部位于第一栏；「设置」经账户行菜单进入主区整页；新增侧栏 chrome 与设置入口的行为需求

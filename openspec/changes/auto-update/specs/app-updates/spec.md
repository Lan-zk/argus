## Purpose

应用内自动更新能力:感知已发布版本与新版本的差异,经用户确认后自动完成下载、完整性校验、安装与重启,把更新成本降为一次点击;检查与下载全程失败安全,绝不破坏当前可用版本。

## ADDED Requirements

### Requirement: 版本检查时机

应用 SHALL 在每次启动完成后静默检查一次新版本,并在设置页「关于 · 检查更新」区块支持用户手动触发检查。除上述两个入口外,系统 MUST NOT 在后台周期性轮询更新。版本比较 SHALL 基于语义化版本:仅当清单版本高于当前运行版本时视为「有可用更新」;同版本或更低版本一律视为「已是最新」。

#### Scenario: 启动静默检查发现新版本
- **WHEN** 应用启动完成且更新源清单中的版本高于当前版本
- **THEN** 应用展示更新提示(见「更新提示与用户确认」),不弹模态阻断使用

#### Scenario: 静默检查失败不打扰
- **WHEN** 启动静默检查因网络错误、更新源不可达或清单缺失而失败
- **THEN** 应用不显示任何错误提示,正常进入使用状态

#### Scenario: 手动检查失败显示可读错误
- **WHEN** 用户在设置页点击「检查更新」且检查失败
- **THEN** 设置页该区块内显示可读的失败原因,并提供再次检查入口

#### Scenario: 手动检查确认已是最新
- **WHEN** 用户手动触发检查且清单版本不高于当前版本
- **THEN** 设置页显示「已是最新版本」及当前版本号

### Requirement: 更新提示与用户确认

发现新版本时,系统 SHALL 展示新版本号与该版本的更新说明(发布说明文本)。下载与安装 MUST NOT 在未经用户确认的情况下自动开始。更新提示 SHALL 可被关闭:关闭后本次运行期间不再自动弹出,但设置页手动检查仍可再次看到该更新。

#### Scenario: 提示包含版本号与更新说明
- **WHEN** 检查发现可用更新
- **THEN** 提示中展示新版本号与该版本发布说明;发布说明缺失时仅展示版本号,MUST NOT 显示占位错误

#### Scenario: 用户确认前不发生下载
- **WHEN** 更新提示已展示且用户未点击「立即更新」
- **THEN** 系统不发起任何更新包下载

#### Scenario: 关闭提示后本次运行不再弹出
- **WHEN** 用户关闭启动检查产生的更新提示
- **THEN** 本次应用运行期间不再自动弹出该提示;下次启动重新检查

### Requirement: 一键更新链路

用户确认更新后,系统 SHALL 依次完成下载(展示进度)、更新包签名校验、安装与重启。签名校验 MUST 使用与更新源清单配套的公钥;校验失败 MUST 拒绝安装并提示错误,当前版本保持可用。下载中断或失败时,系统 SHALL 允许重试或取消,且不影响当前版本运行。安装成功后系统 SHALL 自动重启至新版本。

#### Scenario: 正常更新链路
- **WHEN** 用户点击「立即更新」且下载、校验、安装均成功
- **THEN** 界面展示下载进度,安装完成后应用自动重启并运行新版本

#### Scenario: 签名校验失败拒绝安装
- **WHEN** 下载的更新包签名校验失败
- **THEN** 系统不安装该包,提示更新失败及可读原因,当前版本继续正常运行

#### Scenario: 下载失败可重试
- **WHEN** 更新包下载中断或失败
- **THEN** 界面提示下载失败并提供重试与取消;取消后回到可再次发起更新的状态,当前版本不受影响

### Requirement: 更新源与发布可见性

更新源 SHALL 为本仓库 GitHub 上**已发布**(非草稿)Release 附带的版本清单。草稿 Release 的内容 MUST NOT 被视为可用更新:发布动作即更新的对外开关。版本清单与安装包的传输 MUST 走加密通道(HTTPS)。

#### Scenario: 草稿 Release 不产生更新
- **WHEN** 维护者打了新版本 tag 但 Release 仍为草稿(未发布)
- **THEN** 已装旧版本的用户检查更新时不会看到该版本(表现为「已是最新」或检查失败,均静默)

#### Scenario: 发布后更新可见
- **WHEN** 维护者将新版本 Release 发布
- **THEN** 用户侧随后的版本检查(启动静默或手动)能发现该新版本

### Requirement: 平台覆盖范围

自动更新 SHALL 覆盖 macOS 安装(.app)、Windows NSIS 安装包、Linux AppImage 三种安装形态。Windows 的 MSI 安装形态不在自动更新覆盖范围内;MSI 用户 MUST NOT 收到误导性的「可一键更新」承诺,升级路径为手动下载安装。

#### Scenario: 三平台安装形态可自动更新
- **WHEN** 用户使用 macOS .app、Windows NSIS 安装包或 Linux AppImage 安装的旧版本
- **THEN** 版本检查与一键更新链路对其可用
